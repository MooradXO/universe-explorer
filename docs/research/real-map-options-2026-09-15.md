# Реальная карта космоса: варианты для выбора

Дата проверки: 15 сентября 2026. Статус: **утверждены большой охват, сочетание AT-HYG 4.0 + Gaia DR3 + SIMBAD + NASA NED, объёмная 3D-карта и сохранение возможности монетизации; разрешение ESA не получено**.

Актуальное расширение: пользователь подтвердил полный AT-HYG для локальной разработки, сочетание четырёх источников и свободный полёт внутри системы + варп к выбранной звезде. Полный импорт AT-HYG выполнен и проверен: [evidence](../phases_archive/catalog-import-2026-09-15/README.md). Сейчас письма не отправлять. Роли источников и правила объединения: [архитектура общего каталога](combined-catalog-architecture-2026-09-15.md). Прежние варианты ниже сохранены как контекст выбора.

Пользователь поручил двигаться к карте на реальных данных и попросил спрашивать его перед выбором. Пользователь выбрал B: сразу большая звёздная карта с подробной проработкой отдельных систем. Дополнительно утверждены AT-HYG 4.0 с предварительной проверкой условий, объёмная карта с вращением/приближением/поиском/выбором системы и возможность монетизации. Масштаб, способ перелёта, оформление и связь с домашней базой требуют отдельных решений. Каталоги в runtime пока не добавлялись.

## Проверенные кандидаты в источники

### HYG 4.2 — звёздный каталог

Автор указывает текущую версию 4.2: почти 120 тысяч звёзд; есть имена, положения, расстояния и спектральные сведения. GitHub-репозиторий архивирован, актуальное размещение — Codeberg и сайт автора. [Страница автора](https://www.astronexus.com/projects/hyg), [уведомление о переносе](https://github.com/astronexus/HYG-Database).

Указана лицензия CC BY-SA 4.0. Она предусматривает attribution и ShareAlike для адаптаций; источник и оформление производного набора должны войти в последующее согласование. [Условия CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

Данные `ra/dec` заданы для эпохи 2000.0; `x/y/z` используют экваториальную систему. `dist >= 100000` означает отсутствующий или сомнительный параллакс — такие строки нельзя трактовать как достоверные дальние координаты. [Описание полей HYG](https://www.astronexus.com/projects/hyg-details).

### JPL Horizons — Солнечная система

Сервис выдаёт положения и скорости объектов Солнечной системы для заданного времени и системы отсчёта. Это кандидат для построения орбитальной сцены; выбор даты и точности модели ещё впереди. [Официальное руководство](https://ssd.jpl.nasa.gov/horizons/manual.html).

### AT-HYG 4.0 — выбран пользователем после проверки условий

Актуальный README автора получен через публичный Codeberg API: свыше 2,5 млн звёзд, текущая версия 4.0, сочетание Tycho-2, Gaia DR3 и исторических данных HYG. Автор указывает CC BY-SA 4.0. [Репозиторий автора](https://codeberg.org/astronexus/athyg), [проверенный README через API](https://codeberg.org/api/v1/repos/astronexus/athyg/contents/README.md).

Это более плотная карта, чем HYG. Инженерная оценка: нужен предварительный экспорт по областям и уровням детализации; загрузка всего исходного CSV браузером неприемлема. Размер готовой игровой выборки ещё не измерен, FPS не оценивался.

Официальные страницы ESA успешно прочитаны через Windows HTTPS с обычной проверкой TLS. Gaia распространяется под CC BY-NC 3.0 IGO; условия ESA предусматривают запрос разрешения до коммерческого использования, включая прямую или косвенную финансовую выгоду. Объявленная автором лицензия объединённого набора сама по себе не подтверждает коммерческое разрешение на исходные данные. [Gaia Data License](https://www.cosmos.esa.int/web/gaia-users/license), [ESA archive terms](https://www.cosmos.esa.int/web/esdc/terms-and-conditions).

Пользователь выбрал AT-HYG 4.0, затем подтвердил сохранение возможности монетизации и запрет включать данные в коммерческую версию до разрешения. Позднее согласовано подключение полного AT-HYG в локальную разработку; запрос ESA пользователь откладывает. Не следует считать внутреннюю разработку будущей коммерческой игры автоматически разрешённой до показа людям: условия этого этапа включены в [черновик запроса ESA](esa-gaia-permission-request-draft.md). Письмо не отправлено. Синтетические fixtures можно использовать для тестов независимо от импорта реальных данных.

#### Предварительная техническая проверка

Проверен упорядоченный префикс из 10000 строк, а не весь каталог и не случайная выборка. В нём 9899 строк имеют конечные XYZ, у 101 координат нет; 9959 Gaia ID превышают предел точного целого JavaScript и должны храниться строками. Поля AT-HYG: `x0/y0/z0`; нельзя автоматически применять контракт `x/y/z` HYG. [Машинный отчёт](athyg-4.0-prefix-inspection-2026-09-15.json).

После проверки префикса завершена полная загрузка вне game repo: `project/.catalog-research/athyg-4.0/athyg_40.csv.gz` относительно workspace. Размер — 199688001 bytes, SHA256 совпала с Git LFS pointer: `69ad04dd33d7c7bb4f5e1b4682798075811547ea9fb8d0e802e5b319c46818a6`. Все 2 558 654 строки импортированы локально, два полных импорта совпали. Каталог ещё не включён в игровой runtime и не опубликован. [Полная проверка](../phases_archive/catalog-import-2026-09-15/README.md).

### NASA Exoplanet Archive — известные экзопланеты

TAP позволяет получать выбранные поля из Planetary Systems, Composite Parameters и Stellar Hosts. Кандидат для реальных параметров и карточек систем; архив просит указывать DOI данных. [TAP](https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html), [acknowledgements](https://exoplanetarchive.ipac.caltech.edu/docs/acknowledge.html).

### Gaia — условия источника и разрешение

Gaia DR3 предоставляет гораздо более объёмный набор наблюдений. [Состав DR3](https://www.cosmos.esa.int/web/gaia/dr3). Веб-инструмент вернул HTTP 451, но обычный Windows HTTPS успешно прочитал официальные license/terms без отключения проверки сертификатов. Условия описаны выше; разрешение на коммерческий сценарий Universe Explorer не получено. Это вопрос назначения использования, а не только даты публичного показа.

## Последующие решения

После утверждённых охвата, каталога и формата остаётся представить пользователю:

1. Масштаб карты и систем, настройки уже выбранного перемещения (свободный полёт внутри системы + варп к звезде).
2. Визуальное направление и конкретные изображения/эффекты, включая EpicToonFX.
3. Связь существующей домашней базы с реальными координатами и источники детальных систем. JPL и NASA Exoplanet Archive пока только кандидаты.

## Что подготовлено для будущего подключения

Текущий `SectorManifest` содержит только процедурные звёзды и планеты. Подключение реальных объектов потребует отдельного набора данных с происхождением, единицами, эпохой и устойчивыми идентификаторами; преобразование астрономических координат в игровые координаты должно быть отдельным модулем. Конкретный контракт и коэффициенты ещё не выбраны.

Архитектурные принципы интеграции; первый offline-импорт AT-HYG уже реализован:

- Отдельный offline importer с проверкой строк и отчётом: сколько объектов имеют пригодные 3D-координаты, сколько исключено и почему.
- Исходные единицы и эпоха сохраняются в каталоге; игровой масштаб задаётся независимо после выбора пользователя.
- Сначала небольшой индекс поиска/карты, затем данные видимой области. Для каждой звезды хранится признак наличия подробной системы; плотность звёздного поля не подменяет готовность систем к посещению.
- В renderer передаются только локальные координаты через существующий floating origin. Полные звёздные и планетные visuals создаются при приближении в рамках budgets.
- Подключение существующей базы к новому реальному миру — отдельное продуктовое решение, до него старые игровые сохранения нельзя безусловно интерпретировать как астрономические координаты.

Нельзя автоматически назначать реальной звезде случайные планеты и представлять их как открытые объекты. Прежний home sector с базой, merchant, условной чёрной дырой и 80 процедурными планетами также нельзя просто переименовать в Солнечную систему. Судьбу домашней базы и смешение реальных/вымышленных объектов следует согласовать перед изменением мира.
